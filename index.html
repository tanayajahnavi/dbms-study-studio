CHAPTER 1 · LECTURER PPT

Databases and Database Users

The core question: why use a database system instead of keeping separate files?

1.1 · Start with the idea

Simple explanation: a database is an organised collection of related information. A DBMS is the software that lets people define, build, query, update, share, protect and maintain that database.

Exam-ready definition · PPT wording, simplified

A database represents some aspects of the real world and is a logically coherent collection of data with inherent meaning and a specific purpose. A DBMS is software that enables users to create and maintain a database.

Key vocabulary

  • Data: known facts that can be recorded and have implicit meaning.
  • Mini-world: the part of the real world represented in a database, e.g. students and grades at a university.
  • Database system: DBMS software together with the database data.
  • Metadata: data that describes the structure of other data.

What a DBMS does

  1. Define data types, structures and constraints.
  2. Construct/load the database onto storage.
  3. Retrieve data and generate reports.
  4. Insert, delete and modify records.
  5. Support web access, concurrent sharing, security and maintenance.
Memory hook: Define → Load → Query/Modify → Share safely → Protect & maintain.

1.2 · File-based approach

In early applications, data lived in separate computer files and each application program processed the files it needed. As information grew, duplication and inconsistencies became difficult to manage.

1.3 · Characteristics of the database approach

1. Self-describing nature

The DBMS catalog stores descriptions of database structures and types. This descriptive information is metadata.

2. Program–data insulation

Data descriptions are maintained separately from application programs, reducing the need to rewrite programs for every storage/structure change.

3. Support for multiple views

Different users can see different subsets or presentations of the same database.

4. Sharing & multiuser transactions

Multiple users can retrieve and update data; concurrency control helps keep transactions correct and data consistent.

Exam structure: define the database approach, then explain these four characteristics with one line and one example each.

Database System Concepts and Architecture

How do we describe data, separate user views from storage, and process requests?

2.1 · Data models

Simple idea: a data model is a set of concepts used to describe a database’s structure, operations and constraints.

Conceptual / high-level

Describes data as users understand it. Focuses on entities, attributes and relationships.

User view

Representational

Describes data using structures commonly supported by DBMSs; the PPT lists hierarchical, network and relational models.

Implementation view

Physical / low-level

Describes how data is stored, including record formats, placement and access paths.

Storage view

2.1 · Schema, schema diagram and instance

Schema / intension

The description of the database structure, including fields/attributes. It is specified during design and is not expected to change frequently.

Database state / extension / instance

The actual collection of data stored in the database at a particular moment — a snapshot of its contents.

It separates user applications from the physical database and describes the database at three levels.

Stored databaseActual stored data
LevelWhat it describesExample
External / viewPart of the database for a particular user/group.Faculty sees marks; student sees their own result.

Internal / physicalPhysical representation and storage for performance and space use.Record formats, indexes, file organisation.

Why mappings?

A request begins at the user's view. The DBMS maps it to the conceptual level and then to the internal/storage level. Results are mapped back into the form needed by the user.

Data independence

TypeDefinitionExampleDifficulty (PPT)
Logical data independenceChange the conceptual schema without changing external schemas or associated application programs.Add a new attribute/entity while existing user views continue to work.Harder to achieve.
Physical data independenceChange the internal schema without changing the conceptual schema.Reorganise files, add an index or use a different storage device.Generally easier / common.

Stored data managerdisk access / buffers

Components and supporting utilities

  • DDL compiler: processes schema definitions and stores descriptions in the system catalog/data dictionary.
  • Query compiler/optimizer: processes interactive queries and determines an execution plan.
  • DML precompiler: extracts embedded database commands from host-language programs; the DML and host-language parts are compiled and linked.
  • Runtime database processor: executes query plans, privileged commands and prepared transactions.
  • Stored data manager: controls access to data/catalog stored on disk and may use operating-system services for low-level transfer and buffers.
  • Concurrency control and backup/recovery subsystems: support transaction management and recovery.
  • DBA utilities: loading/conversion, backup, storage reorganisation, performance monitoring, sorting, compression and access monitoring.
  • Other environment tools: CASE tools, data repositories, application development environments and communication facilities for remote/distributed access.
